# 金蝶云星空 Agent 自动化指南

本文档说明如何通过 SDK + MCP + Agent 实现金蝶系统的自然语言自动化操作。

## 核心概念

### 三层架构

```
┌─────────────────────────────────────────────────────────┐
│                    用户交互层                            │
│  "把这个 BOM 录入系统"                                   │
└─────────────────────┬───────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────┐
│                 Agent（LLM + 工具调用）                  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │
│  │ 意图理解     │  │ 数据处理    │  │ 结果汇总    │    │
│  └─────────────┘  └─────────────┘  └─────────────┘    │
└─────────────────────┬───────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────┐
│                   MCP Server                            │
│  24 个金蝶操作工具（查询、创建、审批、附件...）           │
└─────────────────────┬───────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────┐
│                   SDK（API 封装）                        │
│  金蝶 WebAPI 的 Python 封装                              │
└─────────────────────┬───────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────┐
│                 金蝶云星空系统                           │
└─────────────────────────────────────────────────────────┘
```

### SDK vs 官方软件

| 维度 | SDK | 官方金蝶软件 |
|------|-----|-------------|
| **本质** | API 接口封装 | 完整的业务系统 |
| **形式** | 代码库（Python） | 网页/客户端软件 |
| **用户** | 开发者、Agent | 业务人员 |
| **入口** | 命令行/Agent 对话 | 浏览器登录 |
| **优势** | 批量、自动化、AI 化 | 完整 UI、流程配置 |

**核心价值：SDK 是"金蝶的自动驾驶系统"，让程序和 Agent 能操作 ERP。**

### 演进路线：从推理到脚本库

**核心理念：系统越用越好，而不是每次都从头推理。**

```
┌─────────────────────────────────────────────────────────────┐
│                     演进路线                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第一阶段：全推理模式                                        │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 用户指令 → Agent 推理 → 调用 MCP → 执行               │   │
│  │                                                     │   │
│  │ 特点：灵活但慢，每次都要理解意图、规划步骤             │   │
│  │ 缺点：不稳定、重复工作、无法复用                      │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  第二阶段：脚本积累模式                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 用户指令 → Agent 检索脚本库 → 组合执行                │   │
│  │                                                     │   │
│  │ 特点：快速、稳定、可复用                             │   │
│  │ 优势：越用越好，常用任务有现成脚本                    │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  第三阶段：智能编排模式                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 用户指令 → Agent 智能编排 → 脚本 + MCP 组合          │   │
│  │                                                     │   │
│  │ 特点：既有脚本的速度，又有推理的灵活性                │   │
│  │ 优势：新任务用推理，成熟任务用脚本                    │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**脚本库的组织：**

```
scripts/
├── data_import/                 # 数据导入类脚本
│   ├── import_bom_from_excel.py      # 从 Excel 导入 BOM
│   ├── import_materials_from_csv.py  # 从 CSV 导入物料
│   └── import_customers_from_json.py # 从 JSON 导入客户
│
├── data_sync/                   # 数据同步类脚本
│   ├── sync_materials_to_mes.py      # 同步物料到 MES
│   ├── sync_stock_to_wms.py          # 同步库存到 WMS
│   └── sync_bom_to_plm.py            # 同步 BOM 到 PLM
│
├── batch_operations/            # 批量操作类脚本
│   ├── batch_approve_ecos.py         # 批量审批变更单
│   ├── batch_update_materials.py     # 批量更新物料
│   └── batch_delete_drafts.py        # 批量删除草稿
│
├── reports/                     # 报表生成类脚本
│   ├── generate_bom_change_report.py # BOM 变更统计
│   ├── generate_material_usage.py    # 物料使用统计
│   └── generate_inventory_alert.py   # 库存预警报告
│
└── workflows/                   # 完整工作流脚本
    ├── new_product_workflow.py       # 新产品上线完整流程
    ├── eco_approval_workflow.py      # 变更单审批完整流程
    └── material_import_workflow.py   # 物料导入完整流程
```

**Agent 如何使用脚本库：**

```
用户："把这个 BOM 录入系统"

Agent 内部流程：
  1. 检索脚本库 → 发现 import_bom_from_excel.py
  2. 检查参数 → 需要文件路径
  3. 调用脚本 → scripts.data_import.import_bom_from_excel(file_path)
  4. 监控执行 → 成功 48 条，失败 2 条
  5. 返回结果 → 用户

下次遇到相同任务：
  用户："把这个 BOM 录入系统"
  Agent：直接调用脚本（无需推理）✅
```

**脚本积累的来源：**

```
┌─────────────────────────────────────────────────────────────┐
│                   脚本积累过程                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户第一次请求                                              │
│  "把这个 BOM 录入系统"                                       │
│      ↓                                                      │
│  Agent 推理执行（慢）                                        │
│      ↓                                                      │
│  执行成功后，Agent 提问：                                    │
│  "这个任务很常用，要保存为脚本吗？"                           │
│      ↓                                                      │
│  用户确认                                                    │
│      ↓                                                      │
│  自动生成脚本：import_bom_from_excel.py                      │
│      ↓                                                      │
│  下次相同任务直接调用脚本（快）                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**"越用越好"的具体体现：**

| 使用阶段 | 新任务处理 | 重复任务处理 | 系统状态 |
|---------|-----------|-------------|---------|
| **初期** | 推理执行（慢） | 推理执行（慢） | 脚本库：空 |
| **中期** | 推理执行（慢） | 脚本执行（快） | 脚本库：10+ |
| **成熟** | 推理 + 脚本组合 | 脚本执行（快） | 脳本库：50+ |
| **完善** | 智能编排 | 脚本执行（快） | 脚本库：100+ |

**脚本 vs 推理的对比：**

| 维度 | 推理模式 | 脚本模式 |
|------|---------|---------|
| **速度** | 慢（需理解意图、规划步骤） | 快（直接执行） |
| **稳定性** | 低（每次推理可能有偏差） | 高（脚本经过验证） |
| **灵活性** | 高（能处理新任务） | 低（只处理已知任务） |
| **可复用** | 无（每次重复推理） | 高（脚本可复用） |
| **可维护** | 无（无代码沉淀） | 高（代码可维护） |

**最佳实践：混合模式**

```
Agent = 推理能力（处理新任务） + 脚本库（处理成熟任务）

新任务：推理 → 执行 → 成功 → 提示保存脚本
成熟任务：检索脚本 → 直接执行
复杂任务：脚本组合 + 推理编排
```

## 自动化场景

### 场景 1：批量录入 BOM

**传统方式（手动）：**
```
1. 登录金蝶系统
2. 点击"基础资料" → "BOM 管理"
3. 点击"新建"
4. 填写表单（BOM 编号、父件、子件...）
5. 点击"保存"
6. 重复步骤 3-5，录入 50 条
7. 耗时：约 2 小时
```

**Agent 方式（自动化）：**
```
用户："把这个 BOM（Excel表）录入系统"

Agent 处理流程：
  1. 理解意图：批量创建 BOM
  2. 读取 Excel：提取 50 条 BOM 数据
  3. 数据转换：Excel 格式 → 金蝶 API 格式
  4. 调用 MCP：batch_create_boms()
  5. 处理结果：成功 48 条，失败 2 条
  
耗时：约 30 秒
```

## PLM 业务场景说明

### 工程变更单（ENG_ECO）

**业务场景：**

产品已经量产，需要修改设计：
- 供应商停产，需要替代物料
- 设计改进，优化产品结构
- 成本优化，使用更便宜的零件

**变更流程：**
```
工程师提出变更申请
  → 评估影响（成本、库存、客户）
  → 审批
  → 执行变更
  → 更新相关文档
```

**MCP 工具：**
- `get_pending_ecos()` - 查询待审批变更单
- `approve_eco(bill_no)` - 审批通过
- `reject_eco(bill_no)` - 驳回变更

### 图纸管理（PLM_DRAWING）

**业务场景：**

产品图纸需要：
- 版本管理（V1.0 → V1.1 → V2.0）
- 关联物料（每个零件对应哪张图纸）
- 权限控制（谁能看、谁能改）

**典型结构：**
```
物料: 风扇-001
  ├── 结构图纸
  │     └── 风扇装配图.dwg (V1.0)
  ├── 电路图纸
  │     └── 电路原理图.pdf (V2.1)
  └── 零件图纸
        ├── 底座图纸.dwg (V1.0)
        └── 扇叶图纸.dwg (V1.2)
```

**MCP 工具：**
- `search_drawings(material_code)` - 查询物料图纸
- `upload_drawing(file_path, material_code)` - 上传图纸
- `download_drawing(attachment_id)` - 下载图纸

**关联关系：**
```
工程变更单 ECO2026001
    │
    ├── 变更内容：底座加厚
    ├── 影响的 BOM：风扇-001
    └── 需要更新的图纸：
          ├── 底座图纸.dwg (V1.0 → V2.0)
          └── 装配图.dwg (V1.0 → V1.1)
```

## 使用建议

### ✅ 适合自动化的场景

- 批量数据录入（BOM、物料、客户等）
- 定时数据同步（金蝶 ↔ MES/WMS）
- 批量审批（低风险变更单）
- 报表生成（定期统计报告）
- 数据查询（自然语言查询）

### ⚠️ 不适合自动化的场景

- 复杂流程配置（需在官方系统配置）
- 权限管理（需在官方系统配置）
- 在线预览 CAD 图纸（需官方界面）
- 高风险操作（需人工确认）

## 下一步

### 1. 安装依赖

```bash
cd kingdee_mcp_agent/mcp_server
pip install -r requirements.txt
```

### 2. 配置连接

```bash
cp config/settings.example.py config/settings.py
# 编辑 settings.py 填入金蝶配置
```

### 3. 启动 Agent

```bash
cd kingdee_mcp_agent/agent
python agent.py -i
```

### 4. 开始对话

```
你: 查询前5个物料
Agent: [返回物料列表]

你: 帮我创建一个新物料，编码 TEST001，名称 测试物料
Agent: ✅ 已创建物料 TEST001
```

### 5. 积累脚本

```
你: 把这个 BOM 录入系统

你: 保存
```

## 技术路线总结

```
┌─────────────────────────────────────────────────────────────┐
│                    完整技术架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户层：自然语言交互                                        │
│      ↓                                                      │
│  Agent 层：意图理解 + 脚本检索 + 智能编排                    │
│      ↓                                                      │
│  脚本层：积累的成熟工作流（越用越好）                        │
│      ↓                                                      │
│  MCP 层：24 个标准工具（查询、创建、审批...）               │
│      ↓                                                      │
│  SDK 层：金蝶 WebAPI 封装                                    │

```

**核心价值：**
- **初期**：Agent 推理处理任务，灵活但慢
- **中期**：积累脚本库，常用任务快速执行
- **成熟**：推理 + 脚本组合，新任务灵活，成熟任务快速

**一句话：让系统在实战中不断积累能力，越用越聪明，越用越快。**
